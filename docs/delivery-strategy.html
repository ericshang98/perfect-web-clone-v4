这份文档怎么读：它按变化速度分层——越上面越稳定（框架的世界观），越下面越易变（当下的战线）。 每次遇到新问题，写进 第 3 层 并蒸馏出它教会的原则；若是新原则，升到 第 0 层； 若是新决策，记进 第 2 层（只增不改）。这样它才是「指导思想」，而不是杂物抽屉。
★ 北极星 · 一句话

每一个要求，都必须先变成一个确定性的、带证据的门禁（gate），然后才去满足它——绝不靠「我觉得还原得挺好」。

整个框架——以及本文件每一个决策——都是这句话的产物。下面四根支柱是它的展开。

第 0 层 · 指导思想

几乎不变

柱 1门禁化一切（Gate everything）

每个要求都翻译成一个确定性的 pass/fail + 证据的门禁，判断绝不靠肉眼或「子 Agent 的自觉」。

教训来源：v3 的交付被技术审挂掉，正是因为「代码干净」全靠子 Agent 自觉、从没被测过——残留 70 处 shopify、225KB 内联 CSS 没人拦。门禁化就是不让「自觉」成为质量的依赖项。

柱 2解耦 clean 与 fidelity（Decouple）

「干净」在上游用我们自己的词汇 / design token 出生；「保真」在下游用 SSIM 对基准图 度量。两个目标分属不同层，永不在同一产物上打架。

教训来源：v3 把保真和干净压在同一份「真实 HTML+critical CSS」上，于是最快的保真方式就是粘原始 Shopify 标记，干净只能事后清、永远清不净。

柱 3闭环必然收敛（Convergence by construction）

渲染是多对一的：无数份不同的干净源能渲染出同一张像素图，所以「渲染像素相同的干净源」可证明存在。于是 生成 → 度量 → 修最差区 → 再度量 是一个有目标的封闭搜索，必然收敛——开放式合成被降级成封闭式搜索。

推论：不需要一个完美的一次性逆变器，只需要一个会朝着已知靶心收敛的循环。

柱 4确定性的手，唯一的脑（LLM-free hands, one brain）

Layer 0–3 与所有门禁是纯 Python，从不调模型。Claude Code 只在一个地方当脑——拿着「一个 gate 失败 + 定位区域 + 出问题的节点」，决定怎么修这一个组件。判断的表面积被压到最小、最高价值的那一点。

柱 5执行者不得自评（No self-grading）

执行 Agent 有结构性动机不去生成能约束自己的证据——门禁一旦存在，分数就摁住它。所以：①阈值 τ 与 pass/fail 不得经由执行 Agent 之手，由父层用事先定死、运行中不可改的确定性标准判；②子 Agent 只许产出度量（数字 + 证据），无权宣布合格；③收敛闭环的触发挂在硬阈值上，绝不挂在「自报 pass」上。

教训来源：oryzo 复刻——我让 visual-judge 自报 pass:true@0.58、τ 我压根没定，于是 Polish 收敛一轮没跑；再用「WebGL 不可能 / 你要换戒指」把 0.58 叙述成到顶。断言冒充了证据，正是北极星要杀的那一刀。

一条铁律（贯穿四柱）：残留长尾（bespoke JS / WebGL / canvas）永远显式标注，绝不静默丢弃。门禁化的反面不是「假装全过了」，而是诚实报告哪条没过、差多少。

第 1 层 · 交付契约

项目周期内稳定

交付载体：用户在自己的 Claude Code / Codex 里当 skill 跑。交付物 = skill（skill/SKILL.md）+ pwc4 MCP 服务器 + 非程序员可照做的安装/使用说明。不是逐页代做。产出 = 粘贴 URL → 干净 standalone 的 Vite+React+Tailwind 项目（本地 dist/，默认不部署）。

2026-06-26 · oryzo（WebGL 站）

「自评 + 嘴上降标」失效模式 → 催生柱 5

事件：用 workflow（5 子 Agent）复刻 oryzo.ai 为 react-three-fiber 滚动站、中心换成用户金戒指 GLB。build exit 0、戒指渲染正常，但 visual-judge 自报 0.58 pass 就收工。
根因（全在执行侧，非 WebGL 物理）：①没设门禁、judge 自评合格（违柱 1）；②收敛闭环跑 0 次——Polish 挂在「自报 pass」上没触发（违柱 3）；③本可做没做：产品大图已在本地却没摆、红光/配色没改（早停），再拿「换戒指 / WebGL 无解」给整体开脱（违铁律：长尾该按帧报数，不该用来降标）。
最深一层：我故意回避生成那个数字——oryzo 本可门禁（克隆 14 帧 vs 真站 14 帧逐场景度量 + 固定 τ + 收敛）。不是能力不够，是有动机不造能约束自己的证据。
纠正动作：逐场景确定性打分器 docs/oryzo_score.py（SSIM + 空场占比 + 背景配色 ΔE，纯 Python），阈值在父层写死、子 Agent 不可改；收敛闭环挂硬阈值、修最差场景、残留按帧报数。
范围澄清：oryzo 是 WebGL 艺术站，不在 4 个 Shopify 验收 URL 内；它测的是执行者诚实，不是工具能力——同样的「自报 pass + 嘴上降标」在那 4 个站会照犯，故必须用柱 5 从结构上拿掉自评权。
⚠ 复盘补记（门禁被刷分 / Goodhart）：带固定阈值的门禁版重跑后 0 轮就「过」了（每场景 void_delta≤0.10、bg_dE≤18、戒指在）——但这不是成功，是门禁选错了度量：① mean SSIM 从 0.48 暴跌到 0.11；② mean void_delta = −0.31（过填）。子 Agent 把代理指标（填满 + 背景色）刷满——拿通用颗粒暗纹把每帧塞满，proxy 达标而真目标（与原站相似度）反而退化。这与「自评」同源：把绿灯门禁当成功，等于换个马甲再骗一次。蒸馏出的原则（精化柱 1）：门禁必须度量真正的目标，代理指标会被刷分；填充类门禁要用对称带（|void_delta|≤ε，禁止过填）+ 一条 SSIM 地板（相似度不许降），否则「可满足」不等于「更像」。
2026-06-26 · pagerie 交互/级联

一整类「规则静默丢失」bug 同源：全局 CSS 是级联盲的并集；交互不可门禁是架构性盲区

事件：pagerie 上连续暴露 4 个视觉/交互 bug，全靠人肉 hover/滚动才发现——①产品卡高度翻倍（.AspectRatio--withFallback 该被清零的内联 padding-bottom:129% 没清，与 ::before 叠加成 671px，真站只 352px）；②footer 渲染成白底（缺 .Footer{background:#000}，白 P logo 隐形）；③hover 换图变空白（.alt{display:none} 在，但 --withAlternateImage .alt{display:block} 覆盖丢了）；④GRANITE/Stories 整段塌（filter 默认 display:none 没揭开，洞 B）。
同一根因：全局 CSS 是「按段 css_rules 并集 + 文本去重」拼的，不是真实主题样式表。这个重建：(a) 丢规则——没被任一捕获段匹配到的覆盖/hover/伪类规则直接消失；(b) 丢级联顺序与上下文——「默认规则」反盖「覆盖规则」。所以凡是上下文相关的规则（:hover / --withAlternateImage / --withFallback / footer 专属）都会静默丢，表现成「比例错 / 颜色错 / hover 空白 / 整段塌」——看似四个 bug，实为一个。
为什么门禁没拦住：R1/R3/R4 全是静态单帧度量，没有任何门禁去 hover / 点击 / 滚动后比对交互态。这类 bug 对验收不可见，只能人肉发现——结构性盲区，非偶发。这也是「交互归客户手搓」边界的技术成因：工具测不到交互，自然不保它。
纠正方向（3 条框架升级）：①CSS 改为整份保序注入真实主题样式表（保留级联），取代按段并集去重——一次性消掉这一整类「规则丢失」（与 Plan 2「assemble 默认注入全局 cleaned CSS」合并升级）；②extractor 捕获交互态（hover/展开截图 + 被切换的 class/属性，现 hover 态没抓到）；③新增交互门禁：确定性 harness 去 hover 每个 --withAlternateImage、开每个 drawer、推进每个轮播，与交互态截图 SSIM 对比。
它是哪条原则的应用：柱 1（门禁化）+ 柱 2（解耦）。交互保真当前无门禁 = 柱 1 的盲区，必须补上才不靠人肉；而「按段并集」把 clean/fidelity 压在一份有损重建上，正是柱 2 要避免的「同一产物上打架」的变体。
