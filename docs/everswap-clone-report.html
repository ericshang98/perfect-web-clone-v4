EverSwap 复刻效果 + 架构优化报告

复刻目标：everswap.com ｜ 日期：2026-06-30 ｜ 全流程实跑 + 逐阶段诊断
一句话结论：这个站没能复刻出原样。原因不是工具坏了，而是 EverSwap 属于最难的一类站—— 主视觉（那座山）是用代码实时「画」出来的、整个页面布局靠滚动动画编排。 我们能把所有文字内容都抓下来，但它「动起来的样子」是静态网页复刻不了的。 （同类天花板：之前的 oryzo 也是这种。）

① 复刻效果：分场景看

✅ 擅长：网店 / 普通页面

布局、产品图、配色、页脚都能对上，一眼是同一个站。这是主力场景，拿得出手。

⛔ 天花板：滚动动画 / WebGL 站

内容抓得到，但动效编排和代码绘制的主视觉复刻不了。EverSwap、oryzo 都属此类。

③ 全流程逐阶段：哪一步达标

阶段结果说明
抓取内容部分文字全抓到；但滚动站只截到一张几乎全白的图，主视觉（山）是代码画的没抓到
切分区块未达标切了 8 段，但每段坐标全是空的（连续第 3 个站）
组装框架基本可框架建成、全局样式注入有效；但文档写的位置和实际已脱节
逐段写组件未达标取数据只给原始 HTML，不给样式数据 → 「干净重写」走不通（最大问题）
构建打包达标npm build 通过，产物正常
指纹检查达标0 残留
体积检查误报代码 ~55KB 本来达标，但图片被算进同一预算导致误报超标
像不像打分无法用参考图本身是空的 + 坐标空 → 打分等于零信息
最终长相未达标视觉破碎（本质性，受限于站点类型）

④ 架构优化点（按优先级）

P0最该先修 P1高 P2中 P3收尾
P0
抓取阶段

站点类型预分类 + 提前告知天花板

复刻前先判断这是什么站（普通页 / 网店 / 滚动动画站 / WebGL站）。遇到滚动/canvas 站，开工前就告诉用户「这类站只能还原内容、还原不了动效长相」，不要承诺一模一样。

P0
拿数据阶段

get_section_data 必须补齐样式数据

目前每段只返回原始 HTML，不给 css_rules、图片地址、坐标。导致「干净重写」这条路在工具层根本走不通——这是文档和实现最大的脱节，应优先补。

P1
拿数据阶段

动画样式归一化

抓回的 HTML 里标题、文字常被动画临时样式（透明度0、display:none）冻成隐形。要自动剥离/标记这些临时态，否则直接用就是一片空白。

P1
抓取阶段

滚动站多张参考图

对滚动动画站，按滚动进度截多张图（0%/25%/50%…），而不是一张几乎全白的全页图——否则「像不像」根本没法比。

P1
切段阶段

bounds 坐标必须落数

连续 3 个站切出来的段坐标全是空的，导致自动修复定位和逐段打分全部失效。

P2
体积检查

代码预算 / 图片预算分开

现在把图片算进代码预算，图多的站一律误报超标。应分两本账：代码 50–80KB，内容图另算。

P2
抓取阶段

canvas/WebGL 主视觉别静默丢

主视觉是画布画的（如 everswap 的山脉）时，至少截一帧当占位图并登记，别当没看见。

P3
指标

页面高度取真实值并自检

页面高度上报 900，实际 13275，自相矛盾。应取真实滚动高度并和截图高度对账。

P3
文档

SKILL 文档与实现同步

文档说全局样式注入 index.css，实际已改到 public/theme.css 等多处脱节，需更新，免得误导。
